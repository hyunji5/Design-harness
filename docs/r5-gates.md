# R5 게이트

모든 값은 rules.json에 넣는다. 이 문서는 무엇을 셀지를 설명한다.

## 단계별 통과 조건
| 단계 | 통과 조건 | 실패 시 |
|---|---|---|
| S1 보드 | 화면마다 uibowl 링크 개수가 `s1.links_per_screen` 범위 안 (넘어도 실패) | S1 다시 |
| S1 노트 | 레퍼런스마다 `s1.decisions` 중 하나가 있고, `가져옴`마다 `user_stories` 번호 1개 이상 | S1 다시 |
| S2 | `screens`의 화면 섹션이 모두 있고, `s2.keywords`가 해당 화면 섹션에 모두 나옴 | S2 다시 |
| S3 | 프레임 개수가 `s3.frames` 범위 안, 모두 `allowed.frame` 크기, `s3.must_include` 화면 포함 | S3 다시 |
| S3 승인 | s3-approval.md에 `approval.fields`가 모두 있음 (반려일 때는 반려 이유도) | 반려면 S3 다시 |
| S4 | `screens`의 화면이 모두 있고, s4-screens.json의 모든 값이 s4-tokens.json에 있음 | S4 다시 |
| S5 | `allowed` 위반 0건 | S4로 |
| 공통 | 같은 단계 3번 실패 | 멈추고 사람에게 물어봄 |

## S2 PRD 키워드 (PRD 원문에서 뽑음)
값은 rules.json `s2.keywords`에만 있다.

- 행사 달력: PRD에 셀 단어가 따로 없어서 `행사`, `날짜` 2개만 센다.
- 결과 내려받기: PRD 4장에 화면이 정해져 있지 않아서 게임 설정 화면에 둔다.

## ★ 어기면 안 되는 것 검사 (S5에서 S4 화면 텍스트로 셈)
값은 rules.json `must_not_break`에만 있다.
- 버튼(합격·보류·불합격·올리기·적용)은 텍스트 레이어 전체가 같아야 한다 (`exact_text`). "불합격" 안에 "합격"이 들어 있기 때문이다.
- 그 밖의 항목은 포함만 되면 된다 (`contains_text`). 금지 문구가 1개라도 있으면 실패다 (`forbidden_text`).

## 단계 배치 (rules.json·gate.py를 만들며 정함)
- 승인 기록 확인은 S4 게이트에서 한다.
- ★ 규칙 검사는 S5에서 한다. 실패하면 S4로 돌아간다.
- 화면 이름은 PRD 4장에서 괄호와 "화면"을 뗀 것이다 (예: 손님용 휴대폰).

## 사람 승인 지점
- S3 끝 한 곳. 관계자 의견은 모으되 최종 결정자는 나(디자이너).

## 예외
- 예외는 없다. rules.json의 `exceptions`에 내가 직접 적은 것만 인정한다. 에이전트는 이 목록을 고칠 수 없다.
