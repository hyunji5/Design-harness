# R3 파이프라인

## 단계
| 단계 | 묶은 작업 (story-work #) | 도구 |
|---|---|---|
| S1 레퍼런스 | 1 + 2 | uibowl |
| S2 화면 설계 | 3 | – |
| S3 키 스크린 시안 | 4 → 사람 승인 (5) | Figma |
| S4 디자인 시스템·화면 | 6 | Figma |
| S5 가이드 검토 | 7 | – (읽기 전용) |

story-work 5번(관계자 협의)은 단계가 아니라 S3 끝의 사람 승인 지점이다.

## 단계별 입출력
| 단계 | 입력 | 출력 |
|---|---|---|
| S1 | PRD 화면 목록 | 레퍼런스 보드, 레퍼런스 분석 노트 |
| S2 | 분석 노트, PRD | 화면 설계서 (화면 5개) |
| S3 | 화면 설계서, design.md | 키 스크린 시안 2~3개 → 승인 후 확정 컨셉 시안 |
| S4 | 확정 컨셉 시안, design.md | 디자인 토큰, 컴포넌트, 화면 디자인 5개 |
| S5 | S4 결과, design.md, story-service.md | 가이드 검토 결과 |

## S4 내부 순서
토큰 → 컴포넌트 → 화면 순서로 고정한다. 화면을 그리다가 새 토큰이 필요하면 바로 추가하지 않고 토큰 단계로 되돌아간다.

## 되돌아가는 지점
| 실패 | 되돌아갈 곳 |
|---|---|
| S2: PRD 요구사항이 설계서에 빠짐 | S2 다시 |
| S3: 사람이 반려 | S3 다시 (반려 이유를 입력으로 받음) |
| S5: 위반 1건 이상 | S4 |
| 같은 단계 3번 다시 해도 실패 | 멈추고 사람에게 물어봄 |
