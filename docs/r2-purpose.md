# R2 목적

## 매번 달라지는 것 (입력)
- PRD 파일 1개 (지금: docs/prd.md)
- 화면 목록은 PRD의 "만들 화면" 장에서 읽는다. (지금: 행사 달력, 행사 상세, 가게 신청 심사, 게임 설정, 손님용 휴대폰 화면)

## 고정인 것
- docs/design.md (디자인 가이드, 판정 기준)
- 파이프라인 단계 (R3에서 정함)

## 하네스 사용자
- 나(디자이너) 혼자 실행한다.
- 내부 관계자(기획·개발·마케팅)는 하네스를 직접 쓰지 않는다. 사람 승인 단계에서 나를 통해서만 의견을 낸다.

## 완료 기준
PRD에 나온 화면 5개가 모두 390×844 Figma 프레임으로 있고, 가이드 검토 결과의 위반이 0건이며, story-service.md의 "어기면 안 되는 것" 2개에 대한 검사가 모두 통과하면 완료다.

## 범위 밖
- 개발팀 전달. 하네스는 전달 묶음(화면 디자인·디자인 토큰·컴포넌트 + 가이드 검토 결과)까지만 만들고, 실제 전달은 사람이 한다.
